# Pi-Guard Lite 实施任务分解（开发视角）

## 1. 文档说明

这份文档不是“你自己去做什么”，而是按**我来帮你完成这个项目**的视角，把项目从 0 到落地需要做的**所有实施步骤**逐项拆开，明确：

- 每一步要做什么
- 这一步实现哪些功能点
- 用到哪些技术
- 产出什么文件/模块
- 上一步和下一步是什么关系
- 如何判断这一步完成

本文档默认项目基线：

- 项目名称：**Pi-Guard Lite**
- 形态：**单节点树莓派防御系统**
- 目标：**旁路检测 + 风险评分 + 自动封禁 + 自动回滚 + Web 页面**
- 硬件基线：**Raspberry Pi 4B 4GB / Raspberry Pi 5 2GB**
- 预算：**800 RMB 级别**
- 软件原则：**轻量、能跑、能演示、能迭代**

# 14. 最终开发顺序建议

如果按“我直接帮你做”的顺序，最合理的实施路线是：

1. 先做**项目骨架**
2. 再做**数据库和配置体系**
3. 再做**日志输入和解析**
4. 再做**规则检测**
5. 再做**风险评分**
6. 再做**执行器**
7. 再做**探测与回滚**
8. 最后做**Web 页面和联调**

原因是：

- 这样可以最快形成可运行闭环
- 先把“看见 -> 判断 -> 动手 -> 验证”跑通
- AI 模型只是增强，不应该阻塞主链路

# 15. 第一版真正必须完成的最小闭环

如果为了最快交付 MVP，我会优先确保下面这条链路完整：

```text
Suricata 日志输入
-> 事件解析
-> 特征提取
-> 规则判断
-> 风险评分
-> 自动生成封禁策略
-> SSH 下发到 OpenWrt
-> HTTP/TCP 探测
-> 失败则自动回滚
-> 页面展示结果
```

只要这条链路跑通，项目就已经具备“能检测、能处置、能纠错、能展示”的完整闭环。
