# Pi-Guard Lite 排障说明

## 1. Web 页面打不开

检查：

1. 是否已创建并激活虚拟环境
2. 是否已安装 `requirements.txt`
3. 是否已启动：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

4. 是否能访问：

```text
/health
```

---

## 2. 表单提交失败

检查：

1. 是否安装了 `python-multipart`
2. `requirements.txt` 是否完整安装
3. `POST /manual/block`、`POST /manual/unblock` 是否可直接调用

---

## 3. 一直没有策略执行

检查：

1. 风险分是否达到阈值
2. 是否命中白名单
3. `dry_run` 是否开启
4. `/executor/check` 返回是否正常

---

## 4. 一执行就回滚

检查：

1. `config/app.yaml` 中 `probe.default_targets`
2. 目标 URL 是否真实可访问
3. 当前是否只是本地演示环境

如果只是在开发环境演示，可临时：

- 改为可访问的本地健康接口
- 或使用 `--no-probe`

---

## 5. 模型状态不可用

检查：

1. 是否生成 demo 模型：

```bash
python scripts/create_demo_models.py
```

2. `config/app.yaml` 中 `ml.enabled` 是否开启
3. 模型路径是否正确
4. 访问：

```text
/ml/status
```

---

## 6. 数据库被占用

如果测试时出现 SQLite 被占用：

1. 关闭运行中的 Web / pipeline 进程
2. 再执行清理或测试
3. 尽量通过程序接口初始化而不是手工删库

---

## 7. systemd 启动失败

检查：

1. `WorkingDirectory` 是否正确
2. `.venv` 是否存在
3. `ExecStart` 路径是否正确
4. 运行：

```bash
journalctl -u pi-guard-lite.service -n 100
journalctl -u pi-guard-lite-pipeline.service -n 100
```

---

## 8. 真机封禁没生效

检查：

1. `config/executor.yaml`
2. `dry_run=false`
3. SSH 凭据是否正确
4. OpenWrt / Linux 是否存在对应命令
5. block / unblock 命令模板是否适配目标环境
