# Pi-Guard Lite 部署说明

## 1. 适用范围

当前文档适用于：

- Windows 开发机本地验证
- Linux / Raspberry Pi 后续部署
- 单节点 Pi-Guard Lite

---

## 2. 本地开发部署

### 2.1 创建虚拟环境

```powershell
python -m venv .venv
. .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2.2 初始化数据库

```powershell
python scripts\create_demo_models.py
python scripts\process_suricata_file.py tests\samples\suricata_eve.jsonl --apply-policy --run-probe
```

### 2.3 启动 Web 服务

```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

### 2.4 启动主链路服务

#### 处理 Suricata 样例

```powershell
python scripts\run_pipeline_service.py --source suricata --file tests\samples\suricata_eve.jsonl --mode existing
```

#### 处理 auth.log 样例

```powershell
python scripts\run_pipeline_service.py --source auth.log --file tests\samples\auth.log --mode existing --no-policy --no-probe
```

#### 处理 syslog 样例

```powershell
python scripts\run_pipeline_service.py --source syslog --file tests\samples\syslog.log --mode existing --no-policy --no-probe
```

#### 处理 Fluent Bit JSON 行样例

```powershell
Get-Content tests\samples\fluentbit_syslog.jsonl | python scripts\run_fluentbit_stdin.py --no-policy --no-probe
```

### 2.5 运维脚本

Linux / Raspberry Pi 上可用：

```bash
bash scripts/install.sh
bash scripts/start.sh
bash scripts/stop.sh
bash scripts/backup.sh
python scripts/import_model.py anomaly /path/to/model.pkl --version v1
bash scripts/start_fluentbit_bridge.sh
```

## 4. Linux / 树莓派部署思路

### 4.1 推荐目录

```text
/opt/pi-guard-lite
```

### 4.2 建议步骤

1. 拉取代码
2. 创建虚拟环境
3. 安装依赖
4. 初始化数据库
5. 生成或导入模型
6. 修改 `config/*.yaml`
7. 安装 systemd 服务
8. 启动 Web 服务
9. 启动 pipeline 服务

### 4.3 systemd 文件

- `systemd/pi-guard-lite.service`
- `systemd/pi-guard-lite-pipeline.service`
- `systemd/pi-guard-lite-fluentbit.service`
- `systemd/pi-guard-lite-release-expired.service`
- `systemd/pi-guard-lite-release-expired.timer`

### 4.4 Fluent Bit 样板

项目已提供：

- `config/fluent-bit.conf`
- `scripts/run_fluentbit_stdin.py`
- `scripts/start_fluentbit_bridge.sh`

可用于把 Fluent Bit 输出的 JSON 行接入主链路。

## 5. 真机前需要修改的配置

### `config/app.yaml`
- 数据库路径
- probe 目标
- ML 开关和模型路径

### `config/executor.yaml`
- 路由器 / OpenWrt 地址
- 用户名
- 密钥/密码
- block / unblock 命令模板
- `dry_run=false`

### `config/assets.yaml`
- 资产 IP
- 资产重要性
- 负责人

### `config/whitelist.yaml`
- 白名单 IP / 网段 / 域名

---

## 6. 上线前检查

1. `/health` 正常
2. `/executor/check` 正常
3. `tests/` 全部通过
4. demo 模型或真实模型可加载
5. 手工封禁 / 解封可跑通
6. probe 能正常访问核心目标
7. `dry_run` 已按环境设置正确
8. release-expired timer 已按需启用
